# 事故录音转写 · 敏感短语遮蔽预览

披露专员在事故录音转写稿公开前，需要遮蔽数万条敏感短语。本项目是一个
纯前端 React 单页应用：载入 `{ text, patterns }` JSON，以 **Aho-Corasick
多模式匹配 + 线性覆盖并集** 实时生成 `#` 遮蔽预览，并在短语列表中为每条
**当前启用**短语显示其在原文中的**有效命中次数**；支持短语的增改、启停、
删除，以及对单个命中的**单次豁免**（口述史经批准保留的引文），可放弃改动
或采纳为下载稿后继续调整。

> 大量短语彼此嵌套、交叠时，逐词搜索（每词全文字符串搜索）会冻结页面，
> 朴素区间标记还会因命中重叠漏掉或重复计算字符。本实现的耗时**不随命中数
> 增长**：自动机扫描每代码单元 O(1)（摊销），覆盖并集两遍线性扫描，不为
> 每个命中分配任何对象。每条短语的匹配次数也在**同一次扫描**里顺带产出
> （扫描只累计到达状态次数，再按构建顺序逆向汇入失败链，从模式终止节点
> 取数），不遍历输出链、不逐短语重扫，资源消耗只随文本长度、Trie 节点数
> 与模式数线性增长。

## 输入文件格式

JSON 根对象**必须且仅含**两个键：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `text` | string | 最多 **2,000,000 个 UTF-16 代码单元**；只允许换行 `U+000A` 与可打印 ASCII `U+0020..U+007E` |
| `patterns` | string[] | 1..50,000 个**互不重复**字符串；每项长 1..200，字符集同可打印 ASCII（**不含换行**）；总长 ≤ 300,000 |

任何不满足上述约束的文件（含 JSON 解析失败、多余键、重复短语、越界长度、
非法字符等）都使页面显示 **`INVALID_INPUT`** 并**清除当前会话**
（原文、工作集、已采纳稿全部清空，需重新载入合法文件）。

> **编辑与导入同源同组约束**：载入之后的任何增改、启停、删除成功后，工作集
> 仍必须始终满足上表的**聚合约束**（短语数 1..50,000、总长 ≤ 300,000）——
> 与文件导入契约逐字一致。会让候选工作集越界的动作（新增第 50,001 条、
> 修改使总长超过 300,000、删除唯一短语等）在**重算之前**直接报
> **`LIMITS_EXCEEDED`** 拒绝当前动作：不重建自动机、不提交快照，最近一次
> 成功的列表、计数、预览与已采纳稿完整保留。恰在边界（恰好 50,000 条、
> 恰好 300,000 总长、删到恰好 1 条）、启停、筛选、窗口化与合法下载一律
> 保持兼容；因此屏幕上的工作集、采纳稿与下载文件总能被原样重新载入。

示例见 [`sample-input.json`](./sample-input.json)。

## 代码单元语义（固定约定）

1. 一切长度与索引都以 **UTF-16 代码单元**为准（即 JavaScript 字符串的
   `.length` 与下标），不是 Unicode 码位，也不是字节。
2. 合法字符集仅含 `U+000A` 与 `U+0020..U+007E`，它们在 UTF-16 中全部
   **恰好占一个代码单元**，因此在合法输入上“代码单元数 = 字符数”。
   代理项（surrogate，即超出 BMP 的字符如 emoji）、TAB/CR 等控制字符、
   非 ASCII 字符一律不得出现，出现即判非法输入。
3. **匹配区分大小写**：`Abc` 与 `abc` 是不同短语。
4. **匹配不跨换行**：换行只允许出现在 `text` 中，短语不含换行；扫描器在
   每个换行处将匹配状态重置为自动机根状态，任何短语都不可能匹配跨越换行
   的内容。换行本身永远原样保留（不会变成 `#`）。
5. 属于**任意短语的任意完整匹配**的代码单元一律替换为 `#`，但其中被
   **单次豁免**的那一次命中的区间会被剔除（只剔除该次命中，其他短语在同一
   区域的遮蔽仍保留，详见「单次豁免」）；多个匹配交叠、嵌套、相邻时，取所有
   **仍生效**匹配区间的**覆盖并集**——不遗漏任何被覆盖位置，也不重复计数。
   其余代码单元**原位保留**（包括空格、标点、换行）。输出与输入的代码单元
   数始终相等。
6. 每次短语增改、启停、删除后，预览都**从原文完整重算**，不做增量修补、
   不复用上一次的遮蔽结果。

## 每条短语的有效命中次数

短语列表中每一行都显示该短语在原文中的**有效命中次数**（无豁免时即完整
匹配次数；存在单次豁免时为完整匹配数减去被豁免的命中数）：

- **区分大小写**：`Abc` 与 `abc` 各自独立计数。
- **允许自重叠**：`aaaa` 对 `a`、`aa`、`aaa` 的次数分别为 **4、3、2**
  （`aa` 起始于位置 0/1/2，`aaa` 起始于位置 0/1）。
- **不跨换行**：换行处匹配状态回到根，任何骑在换行两侧的出现都不计。
- **零命中显示 `0`；停用项显示「未统计」**（停用短语既不参与遮蔽也不计数）。
- 计数数组与**启用短语同序**；界面按条目在完整工作集中的**原始下标**取数，
  因此无论怎样筛选或滚动窗口化，数字始终对应原来那一条。
- 计数与遮蔽来自**同一次重算**：扫描只累计“到达状态次数”，再按 Trie
  构建顺序（BFS 序）逆向把到达次数汇入各自的失败链父节点，最后从每条
  模式的终止节点取数。不遍历输出链、不逐短语重扫、不为命中分配对象；
  额外内存 O(节点数 + 模式数)，耗时 O(|text| + 节点数 + 模式数)。
  计数以 `Uint32Array` 持有（命中数 ≤ |text| ≤ 2,000,000，绝不溢出）。

## 单次豁免（经批准保留的引文）

披露专员确认某处敏感短语是**获批保留的引文**时，只想放过**这一次命中**，
而不能放过同词在其他位置的出现。工作台在每条**启用**短语行提供“单次豁免
起始代码单元”输入：

- 从该启用短语条目指定原文中的**起始代码单元**（0 基 UTF-16 代码单元）。
  加入前先核实它确为该短语在**同一行内的完整命中**：整数、不越界、定长子串
  逐代码单元相等。短语不含换行，子串相等即蕴含“同线内完整命中”（不可能跨
  换行）。非法位置（非整数 / 越界 / 骑跨换行 / 该处并非完整命中 / 条目停用 /
  短语下标越界）报 **`INVALID_POSITION`**（下标越界沿用 `INVALID_PATTERN`），
  在重算之前拒绝，输入框保留当前值便于修改。
- 豁免数量是**有限**的：每条短语最多 **100** 次、工作集总数最多
  **10,000** 次；越界报 **`LIMITS_EXCEEDED`**，同样在重算之前拒绝。
  对同一 `(条目, 起点)` 重复豁免是**幂等**的（不占新名额）。
- 一次豁免**只放过指定的那一次命中**：同词的其他位置照常遮蔽；也**不抹掉
  其他短语**在同一区域造成的遮蔽。自重叠（`aaaa` 中 `aa` 的三个起点）、
  嵌套、部分交叠、以及**同终点**的长短命中（豁免长词后短后缀在该终点的遮蔽
  保留）都按命中区间逐一正确处理。
- 豁免后，**预览、覆盖字符数与该短语的有效命中次数**（完整匹配数减去被
  豁免的命中数）全部从**同一工作集**（原文 + 启用短语 + 豁免簿）整体重算，
  不做增量修补；行内计数显示“有效次数（豁免 N）”，已豁免位置以可点掉的
  标记列出，点击即撤销该次豁免。
- **生命周期**：修改短语值、停用或删除该短语时，其持有的豁免随之失效并被
  清理（改值即换词、停用项不参与匹配）；**载入新文本**清空全部旧豁免；
  **采纳为下载稿**则固化当时的豁免簿与遮蔽结果，之后再增减豁免只产生新的
  工作预览，不改变已采纳稿，再次采纳才更新；放弃改动把工作集与豁免簿一起
  回滚到基线（已采纳稿或文件载入态）。

### 豁免如何不按全文命中数展开

豁免在算法中**不为全文所有命中建立对象列表**：豁免先按其命中终点（
`start + len − 1`，数量有界 ≤ 10,000）排序；正向扫描只在这些终点记录当时的
自动机状态（O(豁免数) 个定长整数）。反向做覆盖并集时，仅在豁免终点沿失败链
枚举“恰好在此结束”的匹配长度（短语 ≤ 200，总步数 O(豁免数 × 200)，与全文
命中数无关），把该点的覆盖标记替换为**最长的未被豁免匹配长度**后照常线性
合并；其他终点的标记不受影响。被豁免命中的计数沿**完整**终止链独立统计，
因此即使最长匹配仍保留遮蔽，链上更短的被豁免命中也准确计入“有效命中次数”。
额外内存 O(|text| + 节点数 + 模式数 + 豁免数)，满规模 200 万文本、5,000
豁免仍在 3 秒门槛内。

## 重算、原子提交与 COUNT_FAILED

- 载入合法文件，或任何增改 / 启停 / 删除 / **单次豁免增减**，预览与计数都从
  **同一原文与候选工作集（含豁免簿）**整体重算；候选快照只有在自动机构建、
  遮蔽、计数全部成功后才**原子提交**。
- 任一阶段异常时显示 **`COUNT_FAILED`**，并**保留上一次成功的工作集、
  豁免簿、预览、计数与已采纳稿**（界面不替换任何状态，可继续编辑或重试）；
  无效豁免位置 / 豁免越界发生在重算之前，同样保留上次有效预览与已采纳稿。
- 短语值本身非法（空串、重复、越界长度、非法字符、下标越界）仍是
  `INVALID_PATTERN`，发生在重算之前，不会被误报为 `COUNT_FAILED`。
- **聚合约束越界**（候选工作集数量不在 1..50,000 或总长 > 300,000，含
  删除唯一短语）以及**单次豁免越界**（每条 > 100、总数 > 10,000）是
  `LIMITS_EXCEEDED`，同样发生在重算之前：候选被整个拒绝，不构建自动机，
  列表 / 豁免簿 / 计数 / 预览 / 采纳稿成套停留在最近一次完整成功状态。
  工作集数量与总长的闸门集中在 `applyChange` 内（`session.ts`），与导入
  路径共用同一个 `assertWorksetLimits`，因此两条路径不可能漂移。
- **采纳固化下载稿、短语快照与当时的豁免簿**：采纳之后继续调整短语或豁免
  所触发的重算只产生新的预览与计数，**不改变已采纳的下载稿或其格式**；
  再次采纳才更新下载稿。

### 连续操作的串行化（失焦提交 + 紧随点击）

行内改完短语后**立即**勾选启停、点添加 / 删除或采纳，是一次连续手势：
浏览器先在 `mousedown` 阶段让文本框失焦（提交编辑并重算），再在随后的
`click` 阶段执行第二个动作。为此：

- 页面以一份**同步权威快照**（工作集 + 预览 + 计数）为所有动作的唯一
  输入；每个稳定的事件回调都从该权威引用读取“用户刚确认的最新工作集”，
  **整体成功后才推进它**，而不是从渲染闭包里的旧 state 取值。因此同一
  手势中的第二个动作必然作用在第一个动作的结果上，成功动作不会被后一个
  动作静默覆盖。
- 采纳 / 下载同样读取权威引用，固化（或导出）的字符串与当时屏幕可见的
  列表、遮蔽预览、计数**成套一致**，不会固化编辑前的旧工作集。
- 任一动作失败（`INVALID_PATTERN` / `LIMITS_EXCEEDED` / `COUNT_FAILED`）
  **只拒绝自身**：权威引用不推进、不回滚，界面停留在最近一次完整成功
  状态；非法输入的文本框保留当前草稿便于继续修改。
- 行身份与短语值解耦：改值 / 启停是“保位”动作，行节点不重建，失焦后
  同手势的点击始终落在同一组 DOM 上；增删只影响对应行的身份，其他行的
  本地编辑态不串位（见 `src/core/rowIdentity.ts`）。

## 短语编辑与错误码

- 新增或修改时若值为**空串、与现有短语重复（区分大小写）、长度越界、
  含非法字符（如换行/TAB）**，显示 **`INVALID_PATTERN`**，输入框保留
  当前值便于继续修改；工作短语集与**已采纳稿均不被覆盖**。
- 对越界下标的修改/启停/删除同样报 `INVALID_PATTERN`。
- 动作后工作集**数量不在 1..50,000 或总长 > 300,000**（新增第 50,001 条、
  改值使总长超限、删除唯一短语）报 **`LIMITS_EXCEEDED`**：动作整体被拒，
  不触发重算，列表 / 计数 / 预览 / 采纳稿不变；输入框同样保留当前草稿。
  恰好达到任一边界是合法的。
- **单次豁免位置非法**（非整数 / 越界 / 落在换行上 / 该处并非该启用短语的
  完整命中 / 对停用条目豁免）报 **`INVALID_POSITION`**；豁免**数量越界**
  （每条 > 100、总数 > 10,000）报 **`LIMITS_EXCEEDED`**。二者都在重算之前
  拒绝，位置框保留草稿，工作集 / 豁免簿 / 预览 / 采纳稿成套保留。
- **放弃**：把工作短语集与豁免簿一起回滚到已采纳稿（未采纳过时回滚到文件
  载入态）。
- **采纳为下载稿**：把当前预览、短语集快照与豁免簿固化。采纳之后继续调整
  短语或豁免不会改变已采纳稿；再次采纳才更新。
- **下载**：下载文件就是屏幕上“已采纳的下载稿”区域所示的同一字符串，
  UTF-8、无 BOM，逐字符一致（采用 `Blob` 由该字符串直接生成，不经任何转换）。

## 性能

- 满规模（text 2,000,000 代码单元、约 1,700 条启用短语、密集重叠命中）
  在参考环境上重算约 1 秒以内；验收门槛为 **3 秒**（见
  `src/core/masker.test.ts`）。最极端的“两百万个 `a` + 长度 1..200 的
  `a` 短语”（每个位置都有 200 个嵌套命中）同样在该门槛内。
- 自动机记忆化“完成转移”：任何 `(状态, 字符)` 的失败链行走至多发生一次，
  构建与扫描均为线性摊销；补写条目数有界。
- 计数的逆向汇入对每个 Trie 节点只做一次加法（BFS 序逆向），与命中数无关。
- 单次豁免不按命中数展开：仅对有界的豁免终点（≤ 10,000）记录扫描状态并沿
  失败链做至多 200 步枚举，额外内存 O(豁免数)，耗时 O(豁免数 × 200)。
- 结果代码单元以 `Uint16Array` 持有，并按 32K 分块 `String.fromCharCode`
  生成字符串，避免巨型参数列表；额外内存 O(|text| + 节点数 + 模式数 + 豁免数)。

## 测试方法说明（不使用固定结果）

测试**不内置任何遮蔽结果的黄金文件或写死的预期串**：所有遮蔽预期均由一个
与生产实现无关的**朴素预言机**在运行时生成——对每条短语用 `indexOf`
逐位置枚举全部完整匹配（允许重叠），用区间差分求覆盖并集后产出 `#` 串，
再与 AC 实现的输出逐字符比对；**每条短语的匹配次数**由同一个独立
`indexOf` 预言机（并辅以“逐行切开分别计数”的换行预言机）按启用短语顺序
逐位核对。随机数据由固定种子的伪随机生成器产生（可复现，而非固定结果），
覆盖随机文本、深嵌套（1..120 条同前缀游程）、高重叠长文本、换行边界、
大小写区分、空文本、零命中等场景；并显式验证 `aaaa` 对 `a`、`aa`、
`aaa` 分别为 4、3、2，以两百万个 `a` 与长度 1..200 的 `a` 短语守住
三秒门槛。聚合约束的验收覆盖**数量与总长两类边界**：`masker.test.ts`
直接核对 `assertWorksetLimits` 与各编辑原语（49,999/50,000/50,001 条、
299,999/300,000/300,001 总长、删到 0/1 条、改值逼近上界），并确认越界
编辑不修改入参、单条违规仍报 `INVALID_PATTERN`、导入侧仍是 `INVALID_INPUT`；
